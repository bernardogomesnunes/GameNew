# PLAY-22 and PLAY-23: selling at the market, and standing sell orders

Owner's note, 22 November: "on a market we should be able to sell items too not only buy. And set recurrent sells. So with time we produce a lot of items in game. Food for example, ore and stone. It would be nice to take profit of it. Selling should be paid in gold coins to allow to buy new stuff and allow to set daly or every other day sells."

Summary. Every trader buys the goods it sells, at half its cheapest buy price rounded down, minimum 1 coin a lot. A short extra table covers produced goods nobody sells (leather, cotton, copper ingots, grey stone, the six field vegetables). Each trader has a purse of 20 coins a game day, shared by hand sales and orders, so a full market pays at most 80 coins a game day. The trader panel gets a Buy and a Sell switch. At a market you own, a sale can be made a standing order: item, lots, every 1 or 2 game days, taken from your storehouses, coins delivered to your storehouses. Orders live on the market structure in the save. Game days only pass while the game is played, so time away owes nothing.

No game code on this branch. Coders add everything below.

## PLAY-22: selling

### Sell price rule

For an item that any trader sells (goods or rare shelf, any of the 6 traders):

- Lot: the lot of the cheapest offer per unit.
- Coins: `Math.max(1, Math.floor(price / 2))` of that offer.

Then a cap for anything made from a recipe whose inputs can all be bought: the lot pays at most half the cheapest buy cost of the inputs for that many, rounded down, minimum 1. Without it, gold gear is profit: a Gold Helm takes 3 gold (7 coins from Ottavio) and the plain rule pays 9.

Rounded down, so a sale never pays more than half. Every buy price in the game is 2 or more, so the sell price is always below the buy price. Because the rule reads the cheapest offer across all traders, buying from one trader and selling to another loses coins too.

### Who buys what

A trader buys every item on its `goods`, every item on its `rare` list (all of them, any day, any age), and its `buys` rows. `buysFor(trader)` returns `[[item, lot, coins]]` sorted by name.

| Grub | rocks, logs, planks, fruit, carrots, cooked meat, coffee, his rare list, grey stone, sand, gravel, sandstone, leaves, white and dark planks | market tier 0 |

### Worn tools and armour

A tool or armour piece in a slot with `wear` sells for `Math.floor(coins * (1 - wear / durability))`. Under 1 coin it is not offered. A full Iron Cuirass pays 7; one at half wear pays 3.

### The purse

- `PURSE = 20` coins per trader per game day.
- One purse per trader id for the whole world. A second market's Grub shares the first one's purse, so building more markets adds order slots but no income.
- It refills when `Math.floor(days)` changes. State: `this.purses = { day, spent: { [traderId]: n } }` on `DuiltGame`, saved as `purses` in `DuiltGame.toJSON`.
- A sale that would pass the purse sells the whole lots that fit and says so. With no lot that fits: "Grub has no more coins today. Back tomorrow."

### Buy-then-sell-back

Four rules close it:

1. The sell price reads the cheapest buy offer across all 6 traders, rare shelves included, and pays half of it rounded down.
2. Every `buys` row is under the cost of its inputs bought at those prices (table above).
3. A crafted item pays at most half its inputs' buy cost (the cap above).
4. A test (chunk A, test 6) walks every recipe: when every input can be bought and the output can be sold, the output's sell value is below the inputs' buy cost.

Found while checking: the foundry already turns bought gold into profit, with no selling involved. Ottavio sells 3 Gold Ingots for 7 coins; the foundry strikes them into 30. Snikkit's rare shelf: 3 gold for 8, struck into 30. Snikkit's 3 Gold Ore for 8 smelt into 1 gold, struck into 10. Test 6 skips recipes whose output is `coin` until the owner decides (open question 1).

## PLAY-23: standing sell orders

### Data model

On a market structure, `s.orders`:

```js
{
  id: 3,                 // per market, s.nextOrder++
  trader: 'stonemonger', // must live in this market: tradersFor(s.tier)
  item: 'stone',         // must be in buysFor(trader)
  lots: 4,               // 4 x 16 = 64 stone
  every: 1,              // 1 or 2 game days
  next: 12,              // the game day it runs next
  last: { day: 11, lots: 4, coins: 4, short: null }, // or short: 'stock' | 'purse' | 'room' | 'gone' | 'broken'
}
```

Stored in lots, so a lot size change keeps an order's meaning. `lots` is 1 to `Math.floor(PURSE / coins)`: an order cannot ask for more than a full purse.

### Order slots

`orderSlots(tier) = 2 * tradersFor(tier).length`: 2, 4, 6, 8 from Humble to Renowned. Each trader at the market can hold any of them.

### When it runs

- `DuiltGame.tick` checks `Math.floor(this.days) > this.marketDay`. On a change it calls `runSellOrders(day)` once and sets `marketDay = day`.
- The purse refills first, then orders run, market by market (structure order), order by order (`id` order). Hand sales that day get what is left.
- An order with `next <= day` runs. After it runs or is short, `next = day + every`.
- Time away: `days` does not move while the game is closed, hidden or in a menu (`Game.js:8605-8622`), so nothing comes due. After 10 real days away the next order runs at the next day turn after you play, once. This matches "game closed no production".
- A jump of several days in one go (an old save, a debug skip): each order runs once, never in arrears.
- A save from before orders: `marketDay` loads as `Math.floor(days)`, so loading runs nothing.

### Where goods come from

- From storehouses only, never the bag. The bag is what you carry; an order must not empty it while you build.
- Any storehouse, broken ones too, the same set `storeTotals()` and `panel-stores` read. Granaries first (`stores()` order), then the rest in structure order.
- A new helper `takeFromStoresExact(itemId, n)` removes exactly `n` or nothing, returns `n` or 0. Tools are never in orders (each has its own wear), so `buysFor` rows for tools are hidden from Repeat.

### Where coins go

`structures.deliver({ coin })`: storehouses first, `excludes` respected, then the bag. The trader panel's "Take from storehouses" button brings them to the bag. Coins are delivered before goods are taken; if `deliver` fails (no room anywhere), nothing is taken and `short` is `'room'`.

### When something is short

The order sells the whole lots it can: `min(lots, stock / lot, purseLeft / coins)`, rounded down.

| Case | Result | `last.short` |
|---|---|---|
| All 4 lots in stock, purse has 20 | 4 lots sold | null |
| 41 stone in stock (2 lots) | 2 lots sold | `'stock'` |
| 0 stone, or under one lot | nothing taken | `'stock'` |
| Purse has 1 coin left, lot pays 1 | 1 lot sold | `'purse'` |
| Coins have nowhere to go | nothing taken | `'room'` |
| Trader no longer at this market | nothing, order kept | `'gone'` |
| Market broken (`valid` false) | nothing, order kept | `'broken'` |

The next run is still `day + every` in every case.

One toast a day turn sums up every market: "Market: sold 64 stone, 12 fruit for 6 coins. Stone order short." Event `market:sold` with `{ day, sold: [{ marketId, trader, item, n, coins, short }] }`, for achievements and notices.

### Showing and cancelling

- Trader panel, Sell tab, at your own market: "Standing orders (2 of 8)". Each row: item icon, "64 stone every day to Grub", "next in 1 day", last result ("sold 4 of 4" or "short of stone: sold 2 of 4"), and **Cancel** (`data-order-cancel`). Orders for every trader of this market show, not just this trader's, so the count matches the slots.
- Repeat on a tile opens an inline form in the tile, the `.craft-work` pattern (`DuiltUI.js:2560`):
  - "Lots" number field, `inputmode="numeric"`, 1 to the cap, with − and + buttons for phones; a line under it: "= 64 stone, 4 coins".
  - "Every" switch: **Day**, **2 days**.
  - "From your storehouses (320 stone there now)".
  - **Save** and **Cancel**. Enter saves. Slots full: Save says "All 4 order slots are taken. Evolve the market for more."
- Market building panel (`showBuilding` for `type === 'market'`): the same list with Cancel, and "Talk to a trader to add one." No adding there: an order needs a trader and a tile.

### Save and load

- `StructureRegistry.toJSON`: `...(s.orders?.length ? { orders: s.orders, nextOrder: s.nextOrder } : {})`. `loadJSON` spreads `...s` already, so the fields come back.
- `DuiltGame.loadJSON` validates after `structures.loadJSON`: drops orders whose market is not a market, whose `trader` is not in `TRADERS`, or whose `item` is not in that trader's `buysFor`; clamps `every` to 1 or 2 and `lots` to 1..cap; sets `next` to at least `Math.floor(days)`.
- `DuiltGame.toJSON` adds `marketDay` and `purses`.
- Cloud worlds (`net/CloudWorlds.js`) save the same JSON; nothing extra.

## Edge cases

| Case | What happens |
|---|---|
| Market removed (`StructureRegistry.remove`) | Its orders go with it. One toast: "The market's 3 standing orders were cancelled." |
| Market broken | Orders pause with `'broken'`, kept, resume when it is whole. Its traders are not placed (`marketTraders` skips invalid), so no hand sales there. |
| Trader not yet at this market | Not on the panel, so nothing can be sold to them or ordered. The Sell tab's empty-state line under Grub: "Snikkit buys ore and arrives at the market's next level." Orders for a trader who leaves (no current path lowers a tier) pause with `'gone'`. |
| City traders | Hand sales, with their own purse. No Repeat: the stall is not your building. |
| Sandbox / Creative | No Sell tab and no orders run: the bag is endless and coins buy nothing there. `sellTo` and `runSellOrders` return early on `this.sandbox` or `this.inventory.endless`, so an endless bag can never mint coins. |
| Sky Kingdom tax (dark path) | Not taken from sales: it taxes building output (`collect`), and sold goods were already taxed when made. |
| Same item in two orders | Allowed. Both draw from the same stock in `id` order. |
| Item excluded from a storehouse | Orders still take it from that shed: `excludes` steers deliveries in, not goods out. |
| Collection book | Selling the last of an item does not untick it: the book notes an item once. |
| Item removed from `traders.js` later | The order is dropped at load (validation above). |
